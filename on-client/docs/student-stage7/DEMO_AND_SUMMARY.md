# Keshev 시연 순서와 확인 근거

작성일: 2026-10-31 · 범위: `on-client` 앱 · 시작 틀 버전: `0.2.21`.

Keshev는 이 PC의 실측 상태와 서버에서 전달받는 계정·기기·세션 상태를 구분해 보여 주는 앱입니다. 이번 시연은 PC 실측의 두 시점 비교, 보안 관찰 요약, 계정·기기·세션 및 SDP 연결 상태 설명으로 구성합니다.

현재 확인 범위는 로컬 PC 조회와 화면 표시입니다. 실제 SDP·AI 연결과 보안 조치 집행은 확인하지 않았습니다. 아래 시연 대본은 앞으로 따라 할 순서이며, 대본 전체를 연속 시연한 기록은 아닙니다.

학생 구현은 코딩 도구와 함께 작성한 `student/extension.mjs` 및 학생 문서를 뜻합니다. 제공 계측 API나 SDP 엔진을 직접 만들었다고 설명하지 않습니다.

| 영역 | 제공된 기능·구조 | 학생 구현·변경 |
|---|---|---|

학생 구현 코드를 확인한 것과 실제 서버에 연결해 기능을 실행한 것은 구분합니다. 특히 AI·업무 앱·조치 관련 함수가 있다는 이유만으로 실제 연동이 됐다고 쓰지 않습니다.

## 3. 실행 준비와 재현 명령

상세 준비·다운로드·오류 대응은 [실행 안내](../student-stage5/RUN_GUIDE.md)를 따릅니다. 아래는 이번 PC에 Node.js ZIP 배포본이 준비된 상태에서의 명령입니다. 다른 PC에서는 프로젝트 루트를 실제 위치로 바꾸고 실행 파일 준비 여부를 먼저 확인합니다.

새 PowerShell 창에서 아래를 실행합니다. 모든 프로젝트·실행 도구·결과물 경로는 허용 루트 `Keshev` 아래입니다.

```powershell
$keshevRoot = 'C:\Users\K_501\Desktop\ALEPH\Keshev'
$keshevApp = Join-Path $keshevRoot 'git-stage6\on-client'
$keshevNode = Join-Path $keshevRoot 'stage5-runtime\node-v24.19.0-win-x64\node.exe'
Set-Location -LiteralPath $keshevApp
& $keshevNode --version
& $keshevNode --check .\student\extension.mjs
```

기대 결과: 버전 `v24.19.0`, 문법 검사 오류 없음. 문법 검사 통과는 화면 동작이나 SDP 연결 성공의 증거가 아닙니다.

이미 5189 포트에서 이 앱이 동작 중이면 해당 서버를 사용하거나, 새 실행 전에 실행 주체에게 종료를 요청합니다. 이번 대화의 도구가 켠 서버는 원래 작업 폴더의 앱입니다. 현재 Git 작업 폴더에서 직접 재현하려면 기존 서버를 먼저 종료하거나 아래 포트를 5190으로 바꾸고 브라우저 주소도 맞춥니다. 다른 프로그램을 임의로 종료하지 않습니다.

```powershell
$keshevPreviousModulePath = $env:PSModulePath
$keshevPreviousPort = $env:ON_PORT
try {
    $env:PSModulePath = $null
    $env:ON_PORT = '5189'
    & $keshevNode .\src\server.mjs
}
finally {
    $env:PSModulePath = $keshevPreviousModulePath
    $env:ON_PORT = $keshevPreviousPort
}
```

이 명령은 별도 SDP 어댑터·AI·계정 호스트를 설정하지 않은 실행 기준입니다. 기존 담당자 설정이 있는 PC에서는 해당 설정과 허용 범위를 먼저 확인합니다. `PSModulePath` 조정은 이번 실행에만 적용하고 끝나면 복원합니다.

정상 시작 출력은 `케셰브 연결 확인: http://127.0.0.1:5189`입니다. 창을 열어 둔 채 [앱 화면](http://127.0.0.1:5189/)을 엽니다. 종료는 이 명령으로 실행한 창에서 `Ctrl+C`, 재실행은 같은 명령 블록입니다.

PC 조회는 일반 권한으로만 진행합니다. 이번에 별도 허용받은 Windows 접근은 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe` 실행, CPU·메모리·앱 드라이브 용량·네트워크 개수, 방화벽 프로필과 `System`·`Application` 기록 집계 읽기입니다. 새 환경에서도 이 범위가 허용되는지 먼저 확인합니다. 방화벽·보안 설정은 변경하지 않습니다.

## 4. 핵심 기능 3가지 시연 순서

아래 시간은 시연 계획이며 실제로 잰 소요 시간이 아닙니다. 전체 약 4~5분을 기준으로 합니다. PC가 바쁘거나 조회가 느리면 결과를 기다리고, 실패를 예시 값으로 채우지 않습니다.

### 도입 — 제공 화면과 현재 연결 상태 (약 30초)

1. `보호 현황` 화면과 `제공`·`학생 구현 표시` 구분을 보여 줍니다.
2. 현재는 SDP 미연결 실행이므로 상단 로그인 정보·업무 앱·기록·기기·세션에 연결 오류가 표시될 수 있음을 설명합니다.
3. 제공 카드 `내 PC 상태`의 `내 PC 확인`을 한 번 눌러 PC 조회가 별도로 동작하는지 확인합니다. 자동 조회 확인란은 선택하지 않습니다.

읽을 대본:

> 이 앱은 PC에서 직접 읽은 값과 서버 연결 상태를 구분합니다. 공통 화면과 PC 측정 기능은 제공 기능이고, 제가 만든 부분은 학생 영역의 비교·요약·상태 표시입니다. 현재 SDP는 연결되지 않았습니다.

### 핵심 1 — PC 상태와 변화 비교 (약 1분 30초)

1. 학생 영역 `PC 상태와 변화 비교`에서 `비교용 조회`를 누릅니다.
2. 조회 중 안내와 CPU·메모리·디스크의 결과, `[실측]`, 측정 시각을 보여 줍니다. 첫 조회에는 이전 자료가 없으므로 비교 불가 안내가 정상입니다.
3. 잠시 뒤 `다시 조회`를 누르고 이전·이번 조회 시각과 증가·감소·변화 없음 표시를 보여 줍니다. 변화를 만들려고 PC 부하를 인위적으로 높이지 않습니다.
4. `이전 값·단위 상세`를 열어 실제 두 값을 확인합니다. 변화가 작으면 `0.1 GiB 미만`으로 표시될 수 있습니다.

읽을 대본:

> CPU 사용률과 메모리 사용량, 디스크 여유 공간을 두 번 조회해 비교합니다. CPU 변화는 퍼센트포인트, 용량 변화는 GiB입니다. 원형 그래프는 사용률이나 여유율이며 보안 점수가 아닙니다. 두 시점의 차이만 보여 주므로 변화 원인이나 지속 추이를 판단하지 않습니다.

### 핵심 2 — PC 보안 관찰 요약 (약 1분)

1. 같은 조회 아래의 `PC 보안 관찰 요약`으로 이동합니다.
2. 네트워크 인터페이스·IPv4 구성 개수, 방화벽 프로필별 켜짐·꺼짐, 최근 24시간 Windows 경고·오류 건수를 보여 줍니다.
3. `조회 범위와 해석 한계`를 열어 범위와 잘림 여부를 설명합니다. Windows 기록은 `System`·`Application` 합산이며 화면 집계는 최대 5,000건입니다.
4. `이 건수는 침해나 공격 탐지 결과가 아닙니다` 문구를 보여 줍니다. 읽지 못한 항목이 있으면 그 이유를 그대로 설명합니다.

읽을 대본:

> 네트워크·방화벽·Windows 기록을 읽기만 해서 요약합니다. 경고와 오류 건수는 공격 탐지 결과가 아닙니다. 방화벽 프로필이 모두 켜져 있어도 개별 규칙이나 PC 전체의 안전을 확인한 것은 아닙니다. 일반 권한으로 읽지 못한 항목은 확인 불가로 남깁니다.

### 핵심 3 — 계정·기기·세션 및 SDP 상태 구분 (약 1분)

1. 학생 영역 `계정·기기·세션 요약`으로 돌아가 현재 연결 상태와 목록 요약을 보여 줍니다.
2. 상세를 열어 현재는 서버 연결이 없어 계정·기기·세션을 확인할 수 없다는 이유를 설명합니다.
3. PC 보안 관찰 아래의 `SDP 미연결` 안내와 PC 실측 결과를 함께 확인합니다. 해당 안내가 실제 화면에 보였을 때만 캡처 확인으로 기록합니다.

읽을 대본:

> 계정·기기·세션은 연결된 서버의 응답이 있어야 확인할 수 있습니다. 현재는 연결 없음과 확인 불가를 표시합니다. PC 조회가 성공해도 SDP 접속이나 로그인 성공으로 바꾸어 표시하지 않습니다. 이 부분의 실제 연동은 아직 확인하지 않았습니다.

### 마무리 (약 20초)

> 제공 기능의 실측값을 활용한 두 시점 비교와 보안 관찰 요약을 확인했습니다. 실제 SDP·AI 연결, 업무 앱 접속과 조치 집행은 미확인입니다. 확인한 내용과 한계는 실행 기록 및 커밋과 함께 문서에 남겼습니다.

키보드 시연을 추가한다면 `Tab`으로 버튼·상세에 이동하고 `Enter` 또는 `Space`로 조작합니다. 전체 키보드 동선을 실제로 검증한 기록은 아직 없습니다. 실패 화면을 보여 주려고 보안 설정을 바꾸거나 공격·침투 시험을 하지 않습니다.

## 5. 실제 확인 근거

각 근거가 증명하는 범위를 구분합니다. 과거 실측값은 현재 값으로 재사용하지 않으며, 시연에서는 방금 조회한 값과 시각을 읽습니다. 아래에는 설명용 CPU·메모리 수치를 만들지 않았습니다.

### 화면 근거

| 근거 | 확인한 내용 | 범위와 한계 |
|---|---|---|
| 사용자 화면 확인 | 제공 `내 PC 상태`의 6개 항목이 표시된다고 보고 | 사용자 확인이며 도구가 제공 카드 전체를 직접 관찰한 것은 아님 |
| 대화에 첨부한 학생 비교 화면 캡처 | 2026-10-31 14:37:48 KST, 실측 3/3·확인 불가 0개. CPU 33.4%, 이전 조회 14:37:28 KST, 감소 등 변화 방향 표시 | 캡처에 보이는 내용 확인. 모든 변화량의 계산 정확성을 별도 대조하지 않음 |
| 같은 캡처의 보안 관찰 | 3/3 항목 확인·확인 불가 0개, 네트워크 인터페이스 3개·IPv4 구성 3개, 침해·공격 탐지 결과가 아니라는 문구 | 하단 방화벽·Windows 기록·SDP 안내 전체가 캡처에 들어온 것은 아님 |
| 전체 화면 캡처 | 제공·학생 영역 구분, 상단 `연결 없음`, 로그인 정보·업무 앱·기록·기기·세션의 연결 오류 | 실제 SDP 미연결 실행의 화면이며 서버 연동 성공 근거가 아님 |

첨부 캡처는 이 대화에서 확인했으며 이 저장소에 이미지 파일로 추가하지 않았습니다. 당시 캡처는 문구와 단위 표기 수정 전 화면으로, 제목이 `PC 관찰과 변화 비교`이고 용량을 `GB`로 표시했습니다. 현재 학생 코드는 `PC 상태와 변화 비교`, `GiB`로 바로잡았고 계산식은 유지했습니다. 수정 후 화면 전체를 도구가 직접 관찰했다고 기록하지 않습니다.

### 실행 기록 근거

시각은 KST(UTC+9)입니다. 도구가 실제 실행한 출력은 이 대화의 실행 기록과 [실행 안내](../student-stage5/RUN_GUIDE.md)에 정리돼 있습니다.

| 실행·조회 | 실제 결과 | 증명하는 범위 |
|---|---|---|

## 7. 문서 확인과 수동 Git 저장

이번 추가 파일은 `on-client/docs/student-stage7/DEMO_AND_SUMMARY.md` 한 개입니다. 앱 코드·제공 파일·기존 제출물은 수정하지 않습니다. 포장 명령은 실행하지 않고 새 포장 스크립트도 만들지 않습니다.

새 PowerShell 창에서는 변수와 작업 위치를 다시 지정합니다. 아래 명령은 현재 PC에 준비한 로컬 MinGit·인증 설정을 사용하는 수동 절차입니다. 인증 정보 파일을 읽거나 출력하지 않습니다. 인증 저장 위치는 Git 프로젝트 밖의 허용 루트 아래입니다.

```powershell
Set-Location -LiteralPath 'C:\Users\K_501\Desktop\ALEPH\Keshev\git-stage6'
$keshevGit = 'C:\Users\K_501\Desktop\ALEPH\Keshev\stage6-runtime\MinGit-2.56.0.4-64-bit\cmd\git.exe'
$env:GIT_CONFIG_NOSYSTEM = '1'
$env:GIT_CONFIG_GLOBAL = 'C:\Users\K_501\Desktop\ALEPH\Keshev\stage6-runtime\gitconfig'
$env:GCM_CREDENTIAL_STORE = 'dpapi'
$env:GCM_DPAPI_STORE_PATH = 'C:\Users\K_501\Desktop\ALEPH\Keshev\stage6-runtime\credentials'
$env:GCM_INTERACTIVE = '1'

& $keshevGit --no-pager status --short
& $keshevGit add -- on-client/docs/student-stage7/DEMO_AND_SUMMARY.md
& $keshevGit --no-pager diff --cached --check
& $keshevGit --no-pager diff --cached --stat
```

명령은 한 줄씩 실행하고 오류가 나면 중단합니다. 차이 검사에 오류가 없고 이 문서 한 개만 스테이징된 것을 확인한 뒤, 사용자가 아래 커밋을 한 번 실행합니다.

```powershell
& $keshevGit commit -m "PC 기능 시연 순서와 확인 근거 정리"
& $keshevGit rev-parse HEAD
```

커밋 번호와 제목을 확인한 뒤 사용자가 `& $keshevGit push origin main`을 실행합니다. 인증이 필요하면 공식 GitHub 화면에서 직접 승인하며 인증 코드·비밀번호·토큰을 대화에 붙여 넣지 않습니다. push가 거절되면 강제로 덮어쓰지 말고 오류 원인부터 확인합니다.

마지막 확인은 `& $keshevGit rev-parse HEAD`와 `& $keshevGit --no-pager status --short --branch`입니다. 성공한 push 출력과 로컬·원격 커밋 일치가 확인된 시점에만 문서 추가까지 반영됐다고 기록합니다. Git 작업을 하지 않았다면 기능 기준 커밋과 문서의 미커밋 상태를 구분합니다.
